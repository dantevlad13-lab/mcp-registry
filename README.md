# Реестр MCP-подключений

Небольшой веб-сервис: после входа по логину и паролю показывает таблицу подключений к MCP-серверам — название, имя базы, признак «бой / не бой», адрес, кластер, каталог выгрузки. Таблицу можно искать, отбирать и сортировать, записи — добавлять, менять и удалять.

Логины и пароли к самим базам сервис не хранит: таких полей нет, лишнее при записи отбрасывается.

## Запуск

Нужен Node.js 18 или новее. Зависимостей нет, `npm install` не требуется.

```
npm start
```

Сервис откроется на http://127.0.0.1:8787.

При первом запуске создаётся пользователь `admin` со случайным паролем — пароль один раз выводится в консоль. Сменить пароль или добавить пользователя:

```
npm run set-password -- <логин> <пароль>
```

## Настройки

Задаются переменными окружения.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `8787` | Порт |
| `HOST` | `127.0.0.1` | Адрес. Чтобы сервис был виден с других машин — `0.0.0.0` |
| `DATA_DIR` | `./data` | Каталог с данными |
| `COOKIE_SECURE` | не задана | `1` — выдавать cookie только по HTTPS |
| `TRUST_PROXY` | не задана | `1` — сервис стоит за обратным прокси, адрес клиента брать из `X-Real-IP` |

При доступе с других машин ставьте сервис за HTTPS-прокси и включайте `COOKIE_SECURE=1`: по обычному HTTP пароль идёт по сети открытым текстом.

## Развёртывание в Docker

Каждый push в `main` собирает образ `ghcr.io/dantevlad13-lab/mcp-registry:latest` (GitHub Actions).

На сервере:

1. Скопируйте содержимое каталога `deploy` (например, в `/opt/mcp-registry`) и создайте `.env` из `.env.example`.
2. Создайте каталог данных и отдайте его пользователю контейнера: `mkdir data && chown 1000:1000 data`. Готовые `connections.json` и `users.json` можно положить туда же.
3. Запустите: `docker compose up -d`. Если на сервере ещё нет watchtower и autoheal — `docker compose --profile standalone up -d`.

Сервис слушает `0.0.0.0:6969` (порт меняется переменной `HTTP_PORT`). Если `users.json` нет, пароль пользователя `admin` выводится в журнал: `docker compose logs app`.

Создать пользователя или сменить пароль:

```
docker compose exec app node scripts/set-password.js <логин> <пароль>
```

Watchtower раз в 5 минут проверяет реестр и пересоздаёт контейнер приложения при появлении нового образа; autoheal перезапускает контейнеры в состоянии unhealthy. Чтобы watchtower мог скачивать образ без входа в реестр, пакет в GHCR должен быть публичным.

## Данные

Каталог `data` в репозиторий не попадает (см. `.gitignore`).

- `data/connections.json` — список подключений. Если файла нет, он создаётся из `connections.example.json`.
- `data/users.json` — пользователи и хеши паролей (scrypt).

Сессии хранятся в памяти и живут 12 часов; перезапуск сервиса завершает все сессии.

## Работа с таблицей

- Поиск идёт по всем текстовым полям; несколько слов через пробел — должны найтись все.
- Отбор «Все базы / Только бой / Только не бой».
- Щелчок по заголовку колонки сортирует по ней, повторный — меняет направление.

## API

Все запросы, кроме входа и `/health`, требуют cookie сессии.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/login` | Вход: `{"login": "...", "password": "..."}` |
| `POST` | `/api/logout` | Выход |
| `GET` | `/api/me` | Текущий пользователь |
| `GET` | `/api/connections` | Список. Параметры: `q`, `prod=true\|false`, `sort=<поле>`, `order=asc\|desc` |
| `POST` | `/api/connections` | Добавить |
| `PUT` | `/api/connections/<id>` | Изменить |
| `DELETE` | `/api/connections/<id>` | Удалить |
| `GET` | `/health` | Проверка, что сервис жив |

Поля подключения: `title`, `infobase`, `name`, `config`, `url`, `cluster`, `dump`, `note` (строки), `prod`, `allowExecute` (булево).

После 10 неудачных попыток входа с одного адреса вход с него блокируется на 15 минут.
